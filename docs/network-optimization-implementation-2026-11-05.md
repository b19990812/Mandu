## 已实施

### 1. 基础耗时记录

- RCP 开启 collectTimeInfo，记录 DNS、连接、TLS、首包等待、正文传输和请求总耗时；不可用字段记为 -1。每次请求只输出一条 NET_HTTP。
- 调度器记录 queue-wait；首页记录 browse-load；目录区分 catalog-load 和 catalog-save；图片区分 asset-disk-hit 和 asset-ready。
- 只记录源 ID、主机名、静态阶段名和数字。日志不包含漫画路径、查询参数、Cookie、响应正文或签名 URL。日志标签为 HSNetwork。
- 这些计时用于下一阶段采样；本轮没有增加正式界面中的开发入口。

### 2. 详情与目录合并读取

新增可选 SourceCatalog 能力。包子（含 Plus）、漫画柜、漫画库、COPY API、HIP、Vomic、MyComic、JoyACG 使用一次作品元数据获取完成详情与目录解析。RegisteredCatalog 在加载前后保留源版本守卫；CatalogService 保留完整目录检查和单次保存，空快照不覆盖旧目录。

COPY 网页模式保留现有详情密钥和目录读取链路；未声明新能力的源和导入规则继续使用原 details/chapters 流程。

设计取舍：方案最初优先考虑在适配器内缓存。对“同一次刷新获取同一响应”的情况，本轮采用可选合并能力，从结构上减少下载和重复解析，不需要长期保存响应；也避免为了消除一次重复请求而绕过 no-store。原有必选接口和稳定作品/章节 ID 保持不变。

### 3. 漫画库目录与线路复用

- 只对既有允许的只读目录 POST 和 source-lines GET 保留有界内存结果：目录最长 60 秒、线路最长 1 小时，响应可进一步收紧期限。
- 最多 16 项，并发相同读取合并；跨页面使用的键包含站点地址、地址版本、源变更和会话版本。
- 显式目录刷新绕过缓存；图片地址刷新使该源缓存失效。
- 每次使用仍通过原有作品、章节、页数和线路格式校验；没有扩大 POST 路径或方法权限。

### 4. 首页与封面

- 首页缓存首批结果，最多 16 组、每组不超过 500 项，默认新鲜期 5 分钟；旧结果最多保留 30 分钟，允许时先显示旧结果再刷新。
- 缓存键区分源快照、版本、会话、栏目、规范化筛选；手动刷新仍读取网络，分页继续实时请求。
- 源地址、启停/版本和站点会话变化使旧缓存不可复用。no-store/no-cache、max-age、Age、Expires、must-revalidate 和 Vary:* 对保留策略生效。
- MyComic 的浏览器请求仍使用 no-store，所以不保存其派生首页结果；合并详情/目录优化仍生效。
- 同一首页请求独立处理各消费者取消和截止时间；只有无人需要时才取消底层请求。显示缓存期间允许打开卡片。
- 封面共享短期源句柄，避免每张封面都初始化 AppContainer 并重新打开源；相同封面共用正在加载的缓存。每个视图独立持有文件引用，最后一个视图离开才释放。

### 5. 当前阅读页优先

- 增加显式网络优先级；旧调用方保留前缀兼容。
- 总并发仍为 4，每源/域名仍为 2；后台最多全局 3、每源/域名 1，为前台保留容量。一个前台和一个后台可以并行。
- 排队任务随等待时间老化；当前可见页优先。当前页复用排队中的预取时提升原任务，不重复下载。
- 单页和双页点击/手势目标均触发提升；预渲染、远期预取、封面和下载分层。
- 保留用户设置的 20 张等预取窗口、原有取消、截止时间、Retry-After 和完整性校验。未通过增加并发或放宽超时宣称提速。
