# 仿真翻页准备提示真机监控

日期：2026-10-29（Asia/Hong_Kong）。最终版本：0.9.15 / code33。

## 1. 结论

在 BKY-W10 / API26 平板上，使用确认位于前台的合成阅读器，完成 **256次点击翻页和24次独立手势翻页**：

- 两组单页点击均未记录到“正在准备翻页画面…”或“正在准备翻页纹理…”。
- 普通图双页记录到20次“准备画面”，最长32 ms；长图双页记录到39次，最长92 ms。
- 24次真实设备滑动注入均确认进入阅读器的开始/结束处理并提交页码，两类准备提示均为0。
- 正式统计样本中，没有这两类提示持续超过100 ms；“准备纹理”没有被记录到。**画面准备提示尚未完全消失。**

这里统计的是UI提示状态日志及其持续时间，不是通过截图确认的文字实际呈现时长。不能推广为所有真实漫画、快翻速度、RTL、旋转或冷缓存条件下都没有等待。

### 3.3 原生路径与剩余成本

四组点击的成功缓存任务共255次，全部为RGBA；`bgraUploads=0`、`stridedUploads=0`、`rowCopyBytes=0`。这确认本机此次使用了不额外逐像素复制的紧密RGBA路径；BGRA通道映射和特殊行距仍只有此前宿主差分证据。

| 阶段累计总量除以任务数得到的均值 | 普通单页 | 长图单页 | 普通双页 | 长图双页 |
|---|---:|---:|---:|---:|
| 分配读取缓冲及ReadPixels | 74.4 ms | 72.6 ms | 69.1 ms | 74.2 ms |
| 移交缓冲及布局元数据准备 | <0.001 ms | <0.001 ms | <0.001 ms | <0.001 ms |
| GL纹理上传 | 20.2 ms | 19.9 ms | 21.1 ms | 20.3 ms |

组件快照和ReadPixels仍存在。零附加行复制不等于整条链零拷贝；预热使多数准备发生在用户请求前。上述均值不是阶段P95，线程工作可以重叠，不能相加后当作单次翻页等待，也不能仅据此将收益归因于某一项改动。

每10秒采样一次PSS，四组采样最大值依次约313.5、334.6、325.0、352.1 MiB。这是5个样本中的最大值，不是真实内存峰值或长时间压力验收。

## 4. 真机发现并修复的Release接口问题

最初0.9.14 / code32的lab包在XComponent加载时退出，未完成任何翻页。实时日志捕获：

```text
TypeError: o43 is not callable, o43 is undefined
at attach (.../w5.ts:11:98)
```

原因是新增NAPI导出 `prioritize` 没有加入 `entry/obfuscation-rules.txt` 的保留名单。ArkTS调用名称被改写，C++仍导出字面量 `prioritize`。0.9.14正式包的名称缓存同样存在改写，不能作为可用卷页包交付。

本轮修复：

- 在既有原生ABI保留列表补入 `prioritize`。
- 新增最小契约检查，核对C++导出、ArkTS类型声明和混淆保留名单；修改前FAIL（只缺prioritize），修改后PASS。
- 版本提升至0.9.15 / code33，保留0.9.14包和失败记录，不覆盖历史证据。
- 为lab增加 `probeAuto=false` 和手势开始/结束事件，普通default入口继续忽略回放参数。

正式版本与lab版本都完成非增量Release构建和SignHap，334个源码/资源/构建支持文件构建前后及归档时一致；两目标使用相同源码，不同目标定义。10项相关宿主准备/交接检查复跑通过。C++像素/调度代码本轮未变，未重复运行无关或全量测试。
