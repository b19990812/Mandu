# 0.5.1 阅读器预渲染

日期：2026-10-26（Asia/Hong_Kong）。依据0.5.0交接接续；本次用户指定阅读预渲染，未推进M11等其他功能。

## 问题与实现

原ReaderPreloader只准备压缩图片文件；ImageTile在组件出现后才调用TileDecoder生成PixelMap，长图列表cachedCount为0。因此文件已缓存也会出现解码等待。

新增TileWarmCache，在现有文件预取之外，用独立的有界队列准备后2张图片及前1张图片的前2个分块；当前长图每块完成显示后提前准备下一块。在线、离线及本地导入共用此路径。跨图片预解码沿用预取开关和在线仅Wi-Fi策略；同图下一分块只使用已取得的本地图片。不是整章解码，也不保证首次打开前已准备完成。

缓存键含URI、原图尺寸、分块及实际解码宽度；视图上报适配尺寸，ImageTile等待有效布局宽度后才解码，避免先按默认1280宽度再解码一次。命中后转移PixelMap租约给ImageTile；同键在途准备可等待复用，失败回退到可见解码路径。不会提前写入已读或阅读位置。

空闲缓存最多6块/16MiB，最多2个准备任务，使用现有串行TileDecoder。预解码在队列实际执行时检查24MiB总像素门槛，正常显示维持48MiB总像素上限和8MiB单块上限。这里统计显式PixelMap，不包含原生编解码器隐式内存。缓存淘汰不释放已交给视图的像素。预解码期间固定文件引用；取消后迟到结果释放，不重新写入缓存。

后台/离开阅读器、换章、切换模式、布局尺寸变化和重试会清理空闲像素；可见像素继续由组件生命周期释放。页面、VM、解码器职责保持分离；未改数据库schema6、API26/min24及签名设置。
