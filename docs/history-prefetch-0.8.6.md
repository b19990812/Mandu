# 0.8.6 阅读历史按漫画汇总与20张预缓存

日期：2026-10-27，Asia/Hong_Kong。版本0.8.6/code17。API26编译与目标、min API24、数据库schema6保持原状。

## 阅读历史

- 每部漫画只显示一项，内容为最近一次可见阅读的章节、页码和完成状态，按最近阅读时间排序。同名的不同漫画或不同来源仍按稳定漫画ID区分。
- 移除原先按章节读取最近200条的显示截断。旧版的200条是查询限制，没有据此删除逐章数据；已有记录会直接按漫画汇总，无需清空或迁移。
- 相同毫秒内阅读多个章节时，优先当前漫画的续读指针，再按稳定章节ID确定顺序。继续阅读仍进入该章节的已保存位置。
- “隐藏此漫画”隐藏该漫画所有已有章节的历史入口，保留各章节位置、已读状态、书签、收藏和离线数据。再次阅读会重新出现一项漫画记录。
- 主界面历史页和独立历史页面使用相同逻辑。列表计数显示“部漫画”，独立历史页从阅读器返回后刷新；卡片键包含漫画身份与最近记录修订，避免显示旧章节。

底层继续保存逐章进度，汇总由ProgressRepository.history完成：SQL先按漫画筛选最大可见阅读时间，再处理相同时间的稳定顺序；同一漫画仅查询一次作品元数据。没有使用全局条数上限，也没有改动备份格式或数据库结构。

## 图片预缓存

- 新默认值为20张，设置支持2/4/6/10/20张；设置选择、读取校验和保存校验使用同一组选项。
- 单页预取当前页之后20张；双页预取当前组之后20张图片，另保留前一张回看。接近章末时只预取实际存在的图片。
- 现有明确保存的较小数量仍可读取。本次已将当前设备的设置保存为20张，并退出再进入设置确认持久化；重新进入章节生效。
- 预取并发仍最多2个，保留跨页重叠任务与取消机制。预取图片文件进入受字节预算约束的浏览缓存，不把20张同时解码为PixelMap；现有Wi-Fi策略、当前页请求优先级、解码与GPU纹理预算继续适用。
