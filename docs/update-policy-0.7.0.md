# 0.7.0：书架更新策略（M11 第一部分）

日期：2026-10-27。版本 0.7.0 / code10，API26 / min24、schema6 不变。

## 已实现

更新页可选择全部收藏或一个分类，关闭或每 6/12/24/48 小时检查；可限制 Wi-Fi、跳过尚有未读章节的作品、自动下载本轮发现的新章。策略应用于手动检查及前台自动检查。自动检查和自动下载默认关闭，Wi-Fi 限制默认开启。

应用进入前台时检查是否到期，保持前台时每分钟判断一次；后台取消自动更新请求并停止计时。全局运行锁避免不同页面/能力实例重复检查。手动检查离开更新页时取消；已提交的目录和已入队下载保留。

逐部刷新完整目录后，以稳定章节 ID 对比新增章节，再复用现有下载队列。首次无目录时只建立基线，不自动下载全书。本地导入作品跳过。单作品刷新失败保留原目录并继续其他作品；取消/超时停止后续操作。下载网络条件仍遵循已有下载设置。

## 关键文件与边界

- `storage/UpdatePolicyRepository.ets`：有界间隔、分类及布尔策略，复用 reader_settings；不修改数据库结构。
- `business/LibraryUpdateService.ets`：串行刷新、分类/智能跳过、网络检查、新章差集及下载协调，页面不执行源解析或 SQL。
- `app/AppContainer.ets`：依赖组装。
- `vm/UpdatesVM.ets`、`ui/UpdatesPanel.ets`：策略编辑、保存和手动运行结果。
- `entryability/EntryAbility.ets`：前台生命周期触发与取消。

系统 WorkScheduler 尚未接入，后台/杀进程后不会定时刷新。本版不宣称 M11 全部完成。间隔按完整批次的最后一次检查时间计算，失败作品计入结果并按下一周期重试；网络中断/取消不推进该时间。一次检查上限 10 分钟，单作品最多 60 秒。

新策略暂不纳入备份白名单，恢复备份后需重新配置。分类删除不会扩大到全部书架，界面提示重新选择。自动下载入队失败会计数，但目前没有独立持久补偿队列；取消发生在目录提交与下载入队之间时，也需要从目录手动补充下载。系统调度、失败下载持久补偿、多分类组合和按完结状态跳过留待后续。

## 验证与手工步骤

本地 Release CompileArkTS / PackageHap / SignHap 通过。未编写或运行单元/集成/全量回归测试；依用户要求不操作真机，尚未证明真实源更新、UI 操作、计时与自动下载端到端表现。

1. 覆盖安装本版，确认原书架、阅读进度和离线章节仍在；进入「更新」。
2. 选择一个分类，关闭跳过未读，点击检查更新，核对只有该分类的网络作品被刷新；测试取消，原目录应保留。
3. 开启跳过未读，核对带未读章节作品被跳过。开关 Wi-Fi 限制，分别在无网、移动网络和 Wi-Fi 下检查提示与行为。
4. 开启 6 小时自动检查。没有历史检查记录时首次前台轮询会运行；已手动检查过则需要到期。返回后台应停止自动检查，回前台到期后继续检查。
5. 对已有完整目录且确实新增章节的作品开启自动下载，检查队列只加入新章节；首次获取目录不可下载整本。手动下载仍可使用。
6. 重启确认策略保留；删除所选分类后应提示重选且不扩大范围。
