# 0.6.0 原生阅读器翻页修复与验收

日期：2026-10-26，Asia/Hong_Kong。最终Release/default已完成CompileArkTS、PackageHap和SignHap；API26/min24、schema6未改变。版本0.6.0/code8，0.5.0–0.5.2交付目录保留。

用户最新指令：真机验证由用户进行。本轮停止设备操作，不再安装最终包；此前曾覆盖安装0.6.0早期检查点，设备上的同版本号不代表已安装最终修订。最终包必须由用户重新覆盖安装。

## 已定位原因

1. ReaderVM.load在异步请求开始前把asset/companionAsset置空，ReaderPage条件分支移除ReadingCanvas，露出背景，随后重新创建图片节点。文件预取和PixelMap预解码均不能消除这个生命周期断点。
2. ReadingCanvas只在TouchType.Up时判断横向位移并调用换页，没有拖动中的页面位移，也没有相邻页共同存在的显示容器。
3. ImageTile在调整宽度时清理旧像素；之前即便改为保留像素，也是在新PixelMap赋值后立即释放旧PixelMap，早于下一帧接管资源。
4. ReaderAssetCache的共享请求在取消后、Promise退出前仍可被新请求复用。此前在《绍宋》滑条跳页复现CANCELLED；0.5.2已修复，只复用未取消请求。
5. “重试分块”曾在正常加载时无条件显示；现只在真正失败时显示，加载期间显示加载状态。
6. 包子只登记s1.bzcdn.net，真实《绍宋》触发s2.bzcdn.net拒绝；0.5.2已精确补充s2，不放行任意子域名。

## 实现与边界

| 文件 | 职责与改动 |
|---|---|
| reader/PagerWindow.ets | 当前页、前后页的稳定身份窗口，最多3个页面；固定文件引用、取消、淘汰和迟到隔离；不解码整章 |
| ui/HorizontalPager.ets | PanGesture持续更新平移；原页和相邻页同步移动；拖动22%或同向速度超过700vp/s且位移超过12vp完成翻页，否则回弹；100–220ms剩余位移动画；同一时刻只允许一个收尾动画，不积压翻页队列 |
| ui/ReadingCanvas.ets | 保留分块、垂直滚动和缩放；新增首屏可见分块就绪通知；横向翻页容器接管手势时关闭旧抬手换页，未放大时关闭内部横向Scroll |
| ui/ImageTile.ets | 有效布局后解码；加载/失败分开；新图完成解码并经下一帧渲染后的idle回调再通知就绪及释放退休像素；隐藏时统一释放 |
| ui/RetainedCanvas.ets | 纵向单页和双页用旧/新两层交接；新首屏未就绪保留旧画面，不做淡入掩盖；失败提供明确提示 |
| vm/ReaderVM.ets | 水平模式把请求页码与已提交页码分开，动画结束提交页码/位置；原模式下载失败保留旧图和原页码；优先当前资源，不同时重复执行水平PixelMap预热队列 |
| model/ReaderDisplay.ets、pages/ReaderPage.ets、pages/SettingsPage.ets | 提供“水平滑动”和“点击单页”；使用原reader.mode键保存，沿用每漫画覆盖与备份白名单，无数据库迁移 |

水平模式目标页首屏未就绪时不让空白目标进入屏幕，保持当前画面并提示等待；首次开章没有旧内容时显示加载状态。方向为rtl时交换手势对应的上一页/下一页，菜单“上一图/下一图”仍为逻辑页序。图片放大后优先图片内部平移；条漫保留原连续滚动。边界采用最大1.5%的水平弹性拉伸后回正，不移动当前内容露出空白。

相邻页在当前首屏就绪后准备；自动预取遵守预取开关和仅Wi-Fi设置，用户主动拖动/点击目标属于前台请求。已有文件缓存、TileWarmCache的16MiB空闲缓存、TileDecoder的48MiB显式像素总上限/8MiB单块上限保留；这些数字不等于进程RSS或原生codec峰值。横向三页容器中的ImageTile使用相同解码预算，淘汰时释放窗口和组件资源。快速输入在短收尾动画期间不再排队；用户下一次手势由已提交页开始。

**适用范围：跟手动画为水平单页。双页和纵向单页获得画面保留修复，但未改为双页组跟手动画。章末跨章仍使用现有换章流程和明确加载状态，不宣称跨章无缝动画。**

## 用户人工验收

安装最终文件artifacts/0.6.0/hs-mihon-release-default-signed.hap；覆盖安装，切勿卸载或清数据。

1. 书架打开《绍宋》第一章，阅读设置选“水平滑动”，先等待相邻页加载。慢拖到半屏，检查两页同时显示、图片跟随手指；松手后页码只改变一次。
2. 小于约22%宽度慢拖并松手，检查自然回弹且页码不变；短距离同向快速滑动检查完成翻页。连续前后翻20次，检查无重影、页码错乱、卡死或空白帧。
3. 换成从右到左，检查拖动及左右触区方向；滑到第一张/最后一张，确认边界反馈、不越界。菜单逻辑上一图/下一图不能反转。
4. 清楚区分冷加载和已缓存：目标图片还没准备好时，应保留当前页并提示等待；网络失败应显示具体原因及重试，不能先露出空白页。
5. 切换“点击单页”，点击触区正常换页，横向拖动不换页；双击/捏合放大后图片可平移，缩回后可恢复滑动翻页。
6. 检查长图竖向滚动不触发横向翻页、横竖屏切换不提交错页、后台恢复与退出重开恢复正确位置；检查双页和纵向单页的新旧画面交接。
7. 在DevEco Profiler记录固定设备刷新率和同一已缓存章节，连续翻页30秒；记录帧时间P50/P95/P99、超过16.67ms的帧数和连续掉帧、进程内存峰值/回落。再连续阅读10分钟，确认内存无持续增长。冷网络等待独立记录，不混算为动画帧率。

## 第二阶段：真实卷页可行性

本地API26 SDK提供PanGesture/属性动画，也声明drawing.Canvas.drawVertices、纹理坐标与采样绘制接口。当前没有现成卷页模块；普通Swiper平移、Y轴旋转或淡入不是真实纸张弯曲。

建议独立实现CurlRenderer，复用PagerWindow的页资源和提交协议：把当前视口按屏幕分辨率合成为受限纹理，通过圆柱或可展曲面模型构建纹理网格，以手指位置确定折线和曲率；绘制纸张正反面、遮挡、背面明暗以及接触阴影。每帧只更新网格参数，避免重新解码整图。先采用ArkGraphics2D自定义RenderNode；若纹理网格、抗锯齿或阴影无法满足预算，再评估XComponent + Native Drawing/OpenGL ES，并单独管理surface和GPU资源生命周期。

纹理最多覆盖当前和下一视口，不能把数万像素长图整张上传GPU。卷页手势需与单页缩放/垂直滚动互斥；回弹不能提交进度。预算必须包含额外纹理、渲染目标和退休资源，不能只沿用CPU PixelMap统计。

**本轮仅完成可行性分析，未加入“仿真翻页”可选项，也未实现纸张网格。** 按“模式A稳定后再做模式B”的要求，先由用户确认基础滑动与设备预算，再实施真实卷页；不会以现有滑动冒充卷页。
